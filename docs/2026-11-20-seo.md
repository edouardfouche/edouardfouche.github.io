# SEO

**Date:** 2026-11-20
**Scope:** search engine and link-preview metadata of https://edouardfouche.com, as of commit `d872d25`
(after the [maintenance changes](2026-11-20-maintenance-changes.md)).
**Ground rule:** do not change page content or design. Every change below affects only `<head>`,
generated files (`sitemap.xml`, `robots.txt`), front matter, or invisible attributes.

## Observations

Checked in the local build (which reproduces production, see the [site audit](2026-11-20-site-audit.md))
and against the live site.

| # | Area | Observation | Impact |
| --- | --- | --- | --- |
| 1 | Description | Every page had the same `<meta name="description">`: "Personal website of Edouard Fouché". `site.description` was "Personal website". | Search engines saw 26 pages with one description. Results showed a generic snippet or a guess. |
| 2 | Link previews | `og:title` was "Edouard Fouché \| Blog" and `og:description` the same generic text on every page. There was no `og:url`, `og:type`, `og:site_name` or Twitter card tag. | A shared post (LinkedIn, Mastodon, Slack, …) showed the blog's title instead of the post's. |
| 3 | Structured data | No JSON-LD at all. | Search engines could not tie posts to an author, or the site to a person and their profiles. |
| 4 | Sitemap | `/sitemap.xml` returned 404. The live `/robots.txt` was only Cloudflare's managed comment block (content signals), with no `Sitemap:` line. | Crawlers had to discover pages and PDFs through links only. |
| 5 | Titles | `<title>` was "Edouard Fouché \| \<page title\>". | Search results cut titles at about 60 characters, so long post titles lost their distinctive part. |
| 6 | Feed | Two `<link rel="alternate">` tags for `/feed.xml`, both typed Atom, but the feed is RSS 2.0 ([open item 2](2026-11-20-open-items.md#2-rss-feed-is-announced-twice-with-the-wrong-type)). | Feed readers and crawlers got the wrong format, twice. |
| 7 | Meta noise | `keywords` (ignored by Google, contained the typo "livestyle"), `Generator: Sublime Text` (false), `Identifier-URL: www.edouardfouche.com` (not the canonical host). | No benefit; the last one names a non-canonical host. |
| 8 | Markup | `<meta charset>` came after a comment block and the feed links. | Still inside the first 1024 bytes the HTML spec requires, but fragile. |
| 9 | Speed | MathJax was a render-blocking script in the `<head>` of every page; only 2 posts contain math. | Slower first render on every page. Page speed (Core Web Vitals) is a ranking signal. |
| 10 | 404 page | `robots: index, follow` and a canonical pointing to `/404.html`. | Harmless (GitHub Pages serves it with status 404), but contradictory. |
| 11 | Accessibility | The navbar profile links (Flickr, Instagram, LinkedIn, GitHub, RSS) contain only an image with `alt=""`. | The links had no accessible name for screen readers or crawlers. |
| 12 | Redirects | `https://www.edouardfouche.com/` → 301 `http://edouardfouche.com/` → 301 `https://edouardfouche.com/`. `http://www.` takes 3 hops. `/about` → 301 `http://edouardfouche.com/about/` → 301 `https://…/about/`. `edouardfouche.github.io` also redirects through `http://`. | Redirect chains through `http://`. Search engines follow them, but each hop costs crawl time. See [still to do](#what-could-still-be-done), item 2. |

Already fine: canonical URLs (fixed in `9d8598c`), `<html lang="en">`, HTTPS everywhere, internal links
with consistent trailing slashes, and stable permalinks. Some post URLs contain `&`, `'` and
parentheses, which is unusual but valid. Changing them would break inbound links and detach giscus

### Why jekyll-seo-tag and jekyll-sitemap

Both are part of the `github-pages` gem (versions 2.8.0 and 1.4.0 in `github-pages` 232) and on the
GitHub Pages plugin allowlist, so production builds them exactly like the local build, with no
`Gemfile` change. They replace about 40 lines of hand-written Liquid and handle escaping, absolute URLs
and JSON-LD correctly.

### Configuration (`_config.yml`)

- `description`: "Personal website and blog of Edouard Fouché, a French-German data scientist. Articles
  on AI, machine learning, research and careers, plus CV and publications." (158 characters). It is
  the home page's meta description, the fallback for pages without one, and the RSS channel
  description.
- `tagline: Blog`: keeps the home page title "Edouard Fouché | Blog". `title: Blog` was removed from
  `index.md`; otherwise jekyll-seo-tag would title the home page "Blog | Edouard Fouché".
- `author` (name, link to `/about/`): the author of every post in JSON-LD and `<meta name="author">`.
- `social.links`: LinkedIn, GitHub, Instagram, Flickr. These are the profiles the navbar links to, and
  they are emitted as `sameAs` on the home and about pages. Twitter is left out because its navbar link
  is commented out.
- `defaults` → `image`: the press portrait that was already the `og:image` of every page (2500×1667
  JPEG, 300 KB). jekyll-seo-tag then emits `twitter:card: summary_large_image`.

`article:published_time` is 01:00 CEST, which is the same instant as the front matter's
`2026-04-21 00:00:00 +0100`.

### Kept on purpose

- `{% seo %}` also emits `<meta name="generator" content="Jekyll v3.10.0">`. It is harmless.
- `creator`, `Publisher`, `copyright`, `google: notranslate`, `Content-Language`, `X-UA-Compatible`:
  not SEO-relevant, or a deliberate choice of the owner (see items 12 and 13 below).
- The `jekyll-feed` plugin stays enabled. It generates nothing, because the hand-written `feed.xml`
  takes precedence. Only its `{% feed_meta %}` tag was removed.
- jQuery and Bootstrap JS stay synchronous, to keep this change focused (see item 9 below).

## What could still be done

Ordered by expected value. None of these was done, because each needs the owner's accounts, the
owner's judgment, or a change to content or design.

1. **Register with search engines.** Verify the domain in Google Search Console and Bing Webmaster
   Tools (a DNS TXT record in Cloudflare, or `webmaster_verifications:` in `_config.yml`, which
   jekyll-seo-tag supports), submit `https://edouardfouche.com/sitemap.xml`, then check the indexing
   report for excluded pages. Step by step: [SEO follow-up, section 2](2026-11-20-seo-follow-up.md#2-how-to-submit-the-sitemap).
2. **Fix the redirect chains** (observation 12). GitHub Pages builds its redirect URLs with `http://`,
   which suggests that Cloudflare reaches GitHub over HTTP (SSL/TLS mode "Flexible"). With mode "Full",
   GitHub would redirect to `https://` directly. Alternatively, a Cloudflare redirect rule can send
   `www` straight to `https://edouardfouche.com`. Check the current setting in the Cloudflare dashboard
   first. Diagnosis confirmed, with step-by-step instructions:
   [SEO follow-up, section 3](2026-11-20-seo-follow-up.md#3-how-to-fix-the-redirect-chains-in-cloudflare).
3. **Lighter images** ([open item 1](2026-11-20-open-items.md#1-large-images-slow-down-post-pages)).
   Multi-megabyte header PNGs dominate the load time (Largest Contentful Paint) of recent posts.
   Adding `loading="lazy"` to images below the fold would help too.
4. **A share image per post.** Set `image:` in a post's front matter (e.g. its header image) so link
   previews show the post's picture instead of the portrait. Ideal size is about 1200×630. Shrink the
   images first (item 3): LinkedIn rejects images over 5 MB.
5. **Alt text for post images.** Most post images use `![img](…)`, so their alt text is "img".
   Descriptive alt text helps image search and screen readers. Only the author can write it.
6. **Weak excerpts as descriptions.** "Hello World" gets "and welcome ! In this blog, …" and "Almost
   30" gets "I am almost 30…". A `description:` in those posts' front matter would read better in
   search results.
7. **Scholarly profiles.** If Google Scholar, ORCID, DBLP or Semantic Scholar profiles exist, add them
   to `social.links` (`sameAs`) and link them from the about or publications page. None is linked
   today.
8. **Publications for Google Scholar.** Scholar's `citation_*` meta tags expect one page per paper.
   The single publications list does not fit that model. It is only worth building per-paper pages if
   Scholar does not already index the papers through the publishers or arXiv.
9. **Defer jQuery and Bootstrap JS.** They are only used by the navbar collapse plugin, and `defer`
   keeps their order. That would remove two more render-blocking scripts. Re-run the visual and
   mobile-menu check afterwards.
10. **Heading structure.** The blog index renders every post title as an `<h1>`. `_layouts/error.html`
    (the 404 page) closes its `<h1>` with `<h1>` instead of `</h1>`, which creates a stray empty
    heading. The same typo appears in commented-out parts of `_layouts/cv.html`. Fixing it can shift
    spacing, so it needs a visual check.
11. **Doctype.** Post pages (`_layouts/default.html`) declare XHTML 1.0 Strict, the other layouts
    `<!doctype html>`. Both trigger standards mode, so this is cosmetic.
12. **`copyright` meta vs. license.** `<meta name="copyright">` says "All Rights Reserved", while the
    footer and the citation policy publish the content under CC BY-SA 4.0. Pick one.
13. **`google: notranslate`.** This meta tag stops Google from offering a translation of the pages in
    search results. Keep it only if that is intended.
14. **Impressum in search results.** The Impressum contains the operator's postal address and is
    indexable. German law requires it to be reachable, not indexed. Adding `robots: noindex` to
    `impressum.md` is an option.
15. **Twitter card attribution.** `twitter:site` is not emitted, because no Twitter account is
    configured. Add `twitter: username: …` to `_config.yml` only if the account is in use again.
16. **Duplicate poster under two URLs.** Git tracks both `publications/POSTER_DS32020_SGMRD.pdf` and
    `publications/Poster_DS32020_SGMRD.pdf`, with identical content (blob `98370d9`). Production
    (Linux, case-sensitive) serves both, and both are now in the sitemap. A macOS checkout
    (case-insensitive) has only one file, which is why the local build lists 62 URLs and the live
    sitemap 63. `_layouts/publications.html` links only the upper-case name. Suggestion:
    `git rm --cached publications/Poster_DS32020_SGMRD.pdf`. This drops a public URL, which is
    unlikely to have inbound links. **Done:** see [SEO follow-up, section 1](2026-11-20-seo-follow-up.md#1-duplicate-poster-removed).

## Observed during the deploy (not SEO)

The push reported an open Dependabot alert (high) for **rubyzip** < 3.4.0 (path traversal) in
`Gemfile.lock`. rubyzip 2.4.1 comes from `jekyll-remote-theme`, which the `github-pages` gem pins and
which requires rubyzip `< 3.0`. The fix is therefore out of reach without leaving the GitHub Pages gem
set (see [open item 6](2026-11-20-open-items.md#6-dependabot-and-the-github-pages-gem)). The risk is
low: `Gemfile.lock` only affects local builds, and this site does not use a remote theme, so rubyzip
never extracts an archive. Dismissing the alert as "vulnerable code is not actually used" is
reasonable. Re-check when `github-pages` publishes a new version.
